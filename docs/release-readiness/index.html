Release blockers and remaining checks

  1. Offline stock counts still wait for a stock screen after relaunch (#74)

    On the 2.3 build a count queued while the gateway was down stays in the persisted queue for at least 60 seconds after a force quit and relaunch on the checklist, with syncError null, and lands only when Stock check opens. The launch drain in src/features/stock-check/queueDrainGate.ts is registered by useStockCheckStore.ts, which only the three stock routes import, so it never registers on the first screen. Evidence: app-store-2.3-proof/img/74-13 to 74-15 and psql sections 74-13 to 74-16.

  2. Production archive and TestFlight not run (#47)

    docs/release/production-build.md and docs/release/device-session.md are written; eas build and eas submit need David.

  3. Approve the prepared EAS production API-key correction

    Read-only EAS inspection found only a legacy anon key. Non-mutating invalid-JSON probes returned 401 Unauthorized for both production login-with-name and accept-invite with that key. The active project publishable key returns 400 Invalid request body, proving it reaches validation. Adding EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY is prepared, but automatic approval review rejected this persistent remote configuration change without explicit authorization. No EAS value was changed.

  4. Complete local mutation and employee regression coverage

    Manager login and checklist submission succeeded, with a matching local database row. Automatic approval review later blocked the Quick Order Send tap as a possible remote write. Explicit permission for disposable records in the isolated loopback backend is pending. Remaining mutations are not marked as passed.

  5. Validate the signed production archive

    This pass uses a locally ad-hoc-signed simulator Release build and a disposable local backend. Main-checkout signing settings reference Apple team 94WMH54N38; EAS submit references TH8X9F2YUR. Confirm ownership, create and validate the signed archive, and verify its production API, update channel, APNs entitlement and available version/build number.

  6. Complete App Store Connect information

    Confirm the public privacy/support URLs, provider retention and final privacy answers, current age-rating questions, store screenshots, reviewer account and review instructions. Source privacy declarations are an evidenced baseline, not a substitute for the archive privacy report or provider disclosures.

  7. Prove shared-device push isolation

    Logout clears local notifications and deactivates the departing user’s current token when online. Offline logout cannot guarantee server token removal. Verify the server’s device ownership behavior and push delivery after user switching on a physical device before release.

  8. Exercise hardware and external services

    Camera, microphone/voice services, real push delivery, email/invite links and supplier sending require their actual service environments and a physical device. Local fixtures and unit tests do not prove these production integrations.

  9. Residual dependency advisories

    After compatible updates, npm audit remains red: 29 affected package entries, 8 high and 21 moderate, zero critical. Four underlying advisories concern image-size, decode-uri-component and uuid. Detailed caller analysis is in dependency-audit.md; no unproven upgrade was forced to make the count green.
